# Проверка и рендеринг диаграмм

Все исходники в `docs/diagrams/*.puml` самостоятельны: внешних `!include`
нет, каждый файл можно рендерить независимо от остальных.

## Вариант 1 — через публичный сервер Kroki (нужна сеть)

```sh
python tools/render_diagrams.py
```

Требуется Python 3, дополнительных пакетов не нужно. Скрипт отправляет
содержимое каждого `docs/diagrams/*.puml` на `https://kroki.io/plantuml/`
и сохраняет `.svg` и `.png` рядом с исходником. При ошибке HTTP,
невалидном XML в ответе или признаках ошибки компиляции в ответе сервера
скрипт завершается с исключением — результат не сохраняется.

## Вариант 2 — полностью офлайн (нужна Java)

```sh
java -jar plantuml.jar -checkonly docs/diagrams/*.puml
java -jar plantuml.jar -tsvg docs/diagrams/*.puml
java -jar plantuml.jar -tpng docs/diagrams/*.puml
```

`plantuml.jar` скачивается отдельно (в репозиторий не включён). Диаграмме
классов для компоновки требуется установленный Graphviz.

## Что делать с результатом

После рендеринга стоит визуально просмотреть каждую диаграмму (переносы
строк в дорожках, отсутствие наложений текста) и обновить ссылки на
`.svg`/`.png` в корневом `README.md`, если изображения сохраняются в
репозиторий. Подробнее о том, что уже проверено без рендеринга и что
нужно проверить дополнительно — в [docs/verification.md](../docs/verification.md).
