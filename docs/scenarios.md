# Сценарии для защиты

Числа ниже — ручные примеры последовательностей событий для иллюстрации
правил модели, а не результаты экспериментов. Источники: 1 — Премиум-подписка,
2 — Мобильное приложение, 3 — Веб-сайт. Заявки обозначены `источник.номер`,
например `2.1` — первая заявка от Мобильного приложения. Буфер вместимостью
N = 3, курьеров — 2 (К1, К2).

## HappyFlow

Буфер пуст, оба курьера свободны, активного пакета нет. Поступает заявка 2.1.

1. Диспетчер постановки ставит 2.1 в конец буфера (Д1ОЗ2) — буфер: `[2.1]`.
2. Диспетчер выбора: буфер не пуст, есть свободный курьер (К1, Д2П1).
3. Пакет не сформирован → определяется источник 2 (единственный в буфере) →
   пакет `{2.1}`, `activeBatchPendingCount = 1`.
4. 2.1 извлекается из буфера — буфер: `[]`. Назначается курьеру К1.
5. Ожидание заявки 2.1 равно нулю.
6. По завершении обслуживания К1 освобождается, `activeBatchPendingCount = 0`,
   пакет закрыт. Буфер пуст — новый пакет не формируется.

## Отказ при переполнении

Буфер заполнен: `[2.2, 3.1, 1.2]`, оба курьера заняты. Поступает заявка 1.3.

1. Диспетчер постановки проверяет буфер — мест нет.
2. По Д1ОО5 отказ получает именно 1.3; буфер остаётся `[2.2, 3.1, 1.2]`
   без изменений.
3. Статистика источника 1 фиксирует +1 отказ; 1.3 выходит из системы без
   обслуживания.

## Занятость курьеров без переполнения

Буфер `[2.2]`, оба курьера заняты. Поступает заявка 3.1.

1. Место в буфере есть → 3.1 ставится в конец: буфер `[2.2, 3.1]`.
2. Диспетчер выбора уведомлён, но свободных курьеров нет (Д2П1 не находит
   ни одного) — обе заявки остаются ждать в буфере.

## Пакет не расширяется

Активный пакет источника 2: `activeBatchSourceId = 2`,
`activeBatchPendingCount = 2` (одна заявка 2.3 в буфере, одна 2.2 уже
обслуживается курьером К1). Буфер: `[2.3]`. Поступает новая заявка 2.4.

1. 2.4 ставится в конец буфера (место есть): буфер `[2.3, 2.4]`.
2. Так как пакет уже сформирован и фиксирован, 2.4 в его состав не входит,
   хотя принадлежит тому же источнику.
3. Освобождается К2 → берёт из буфера 2.3 (единственную заявку текущего
   пакета) — буфер `[2.4]`, `activeBatchPendingCount` не меняется
   (2.3 перешла из «ожидает» в «обслуживается», но всё ещё учитывается).

## Курьер простаивает при активном пакете

Активный пакет источника 1: `activeBatchPendingCount = 1` (заявка 1.5
обслуживается курьером К1). Буфер: `[2.5]` — только заявка другого источника.
Освобождается курьер К2.

1. Диспетчер выбора: буфер не пуст, курьер К2 свободен.
2. Пакет активен (`activeBatchSourceId = 1`), но в буфере нет заявок
   источника 1.
3. К2 не берёт 2.5 — остаётся свободным, ожидая завершения текущего пакета.
4. Когда К1 завершает 1.5, `activeBatchPendingCount = 0`, пакет закрыт.
   При следующем триггере формируется новый пакет по источнику 2 — К2 (и К1,
   если уже свободен) получают заявку 2.5.
