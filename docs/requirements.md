# Соответствие требованиям первичных артефактов

Основание: методическое пособие по СМО и памятка по артефактам №1.

| Требование памятки | Где выполнено |
| --- | --- |
| Сиквенс-диаграммы | [sequence-main](diagrams/sequence-main.puml), [sequence-happy](diagrams/sequence-happy.puml), [sequence-overflow](diagrams/sequence-overflow.puml), [sequence-batch](diagrams/sequence-batch.puml) |
| Диаграмма классов | [classes](diagrams/classes.puml) |
| Блок-схема с дорожками, все альтернативы варианта | [flowchart](diagrams/flowchart.puml), [flowchart-dispatch](diagrams/flowchart-dispatch.puml) |
| Общий сиквенс: отказ через переполнение буфера и занятость приборов, затем постановка заявки | Раздел «Сквозной сценарий» в [sequence-main](diagrams/sequence-main.puml) |
| HappyFlow (буфер свободен, прибор свободен) | [sequence-happy](diagrams/sequence-happy.puml) и первый раздел sequence-main |
| Отдельно: отказ заявки / выбивание | [sequence-overflow](diagrams/sequence-overflow.puml). Выбивания в Д1ОО5 нет — отказывает именно новая заявка |
| Отдельно: постановка / выборка из буфера | sequence-happy, sequence-overflow, sequence-batch |
| Отдельно: постановка на прибор | sequence-happy, sequence-batch, flowchart-dispatch |
| Расшифровка кода варианта рядом с взаимодействиями (п. 2.1) | Примечания `note` на каждой сиквенс-диаграмме и в легендах блок-схем: ИЗ1, Д1ОЗ2, Д1ОО5, Д2Б5, Д2П1, ПЗ2 |
| Ответ в виде Response message | Пунктирные сообщения `-->` на всех сиквенсах |
| Приборы не отказывают, только буфер | В диаграммах курьер либо свободен, либо занят; отказ есть только в ветках буфера (Д1ОО5) |
| Диспетчеры действуют по триггерному событию | В flowchart и flowchart-dispatch запуск диспетчера выбора явно привязан к двум событиям — добавлению заявки и освобождению курьера; описано в [model-rules.md](model-rules.md) |
| Пакетная обработка: пакет — заявки одного источника, доступные при освобождении прибора | Формализовано в [model-rules.md](model-rules.md), реализовано в flowchart-dispatch и sequence-batch |
| Класс-диаграмма: методы + ссылки на сущности | [classes.puml](diagrams/classes.puml) — приватные поля-ссылки у диспетчеров на буфер, курьеров и календарь; методы принимают заявки/курьеров как аргументы |
| Инкапсуляция: приватные поля | Все поля классов в `classes.puml` отмечены как `-` (private) |
| Бизнес-домен указан | [business-domain.md](business-domain.md) |
| Временная диаграмма не визуализируется | Не включена; состояние модели в ОД3 дано таблицей, см. [model-rules.md](model-rules.md) |
| ArchiMate 3.0 | Не включена — согласно памятке опциональна |

## Границы этапа

Экономическое обоснование и сравнительная таблица конфигураций относятся к
итоговому отчёту после реализации программы (п. 3 раздела «Формат итогового
отчёта» памятки) и на уровне первичных артефактов не заявляются.
